## 用户问题

> 帮我分析一下 opencode 桌面端为什么不支持 /skills 命令，为什么不像 tui 那边那样设置一个 /skills 命令弹出一个框来查看所有的技能，而是将技能作为 /命令

## 分析结论

桌面端**不是不支持 skill**，是采用了不同的暴露策略——把 skills 当普通命令内联展示 + 徽章区分。但确实没做 TUI 那种"排除主列表 + 单独 `/skills` 弹窗"的能力；这不是架构限制，是个**待补的功能**，而且在 skills 数量多的时候是个**真实可感的体验缺陷**。

## 实施计划

### 关键决策（用户确认）

1. **过滤范围**：只过滤 skill（不动 mcp）
2. **选中后行为**：写回输入框 `/<skill> ` + 光标在末尾
3. **命令分类**：新建 `command.category.skill`
4. **i18n**：全量更新所有 18 个语言文件

### 新建 DialogSelectSkill 关键代码

```tsx
import { Component, createMemo, createResource, Show } from "solid-js"
import { useSDK } from "@/context/sdk"
import { usePrompt } from "@/context/prompt"
import { useDialog } from "@opencode-ai/ui/context/dialog"
import { useLanguage } from "@/context/language"
import { Dialog } from "@opencode-ai/ui/dialog"
import { List } from "@opencode-ai/ui/list"

export const DialogSelectSkill: Component = () => {
  const sdk = useSDK()
  const dialog = useDialog()
  const language = useLanguage()
  const prompt = usePrompt()

  const [skills] = createResource(async () => {
    const result = await sdk.client.app.skills()
    return result.data ?? []
  })

  const items = createMemo(() =>
    (skills() ?? [])
      .map((s) => ({
        name: s.name,
        description: s.description?.replace(/\s+/g, " ").trim(),
      }))
      .sort((a, b) => a.name.localeCompare(b.name)),
  )

  const handleSelect = (item: { name: string; description?: string } | undefined) => {
    if (!item) return
    dialog.close()
    const text = `/${item.name} `
    prompt.set([{ type: "text", content: text, start: 0, end: text.length }], text.length)
    requestAnimationFrame(() => {
      requestAnimationFrame(() => {
        const editor = document.querySelector(
          '[data-component="prompt-input"]',
        ) as HTMLElement | null
        if (!editor) return
        editor.focus()
        const range = document.createRange()
        const sel = window.getSelection()
        range.selectNodeContents(editor)
        range.collapse(false)
        sel?.removeAllRanges()
        sel?.addRange(range)
      })
    })
  }

  return (
    <Dialog
      title={language.t("dialog.skill.title")}
      description={language.t("dialog.skill.description")}
    >
      <List
        search={{ placeholder: language.t("common.search.placeholder"), autofocus: true }}
        emptyMessage={language.t("dialog.skill.empty")}
        key={(x) => x?.name ?? ""}
        items={items}
        filterKeys={["name", "description"]}
        sortBy={(a, b) => a.name.localeCompare(b.name)}
        onSelect={handleSelect}
      >
        {(i) => (
          <div class="w-full flex flex-col gap-0.5 min-w-0">
            <span class="truncate text-13-regular text-text-strong">{i.name}</span>
            <Show when={i.description}>
              <span class="text-11-regular text-text-weaker truncate">{i.description}</span>
            </Show>
          </div>
        )}
      </List>
    </Dialog>
  )
}
```

## 设计要点

### 为什么不用 onSelect 回调？

TUI 把 `onSelect` 透传到父组件（输入框是简单字符串）。桌面端 `PromptInput` 是 `contenteditable` + 复杂的 parts store：
- `reconcile`（prompt-input.tsx:790-798）只重新渲染 DOM、**不读** `store.cursor`
- DOM 的 `currentCursor()` 在 `clearEditor` 后是 `null`

→ 必须在 dialog 内用 `document.querySelector('[data-component="prompt-input"]')` 定位 + `range.collapse(false)` 设置 cursor

### 6 个新 i18n key

```
command.category.skill
command.skill.show
command.skill.show.description
dialog.skill.title
dialog.skill.description
dialog.skill.empty
```

每个 i18n 文件必须显式列出（类型强制 key 集合对齐）。

## 边缘情况处理

| 情况 | 处理 |
|---|---|
| 没有 skill | `createResource` 返回 `[]` → `emptyMessage` |
| SDK 调用失败 | `skills() === undefined` → `?? []` 兜底 → 同上空状态 |
| Skill 名为 "skills" | 过滤规则只过滤 `source === "skill"`，builtin `id: "skills.show"` 唯一 |
| Dialog 打开时编辑器已清空 | `handleSlashSelect` 的 builtin 分支已经 `clearEditor()`，弹窗关闭后 `prompt.set` 重新设置 text |
| 用户按 Escape 关弹窗 | 弹窗关闭，编辑器为空，无副作用 |
| 双 rAF 失败 | `requestAnimationFrame` 兜底：`querySelector` 返回 null 直接 return |
