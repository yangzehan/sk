## ⚠️ 生产部署关键注意事项（必读）

### 1. clickhouse-keeper-converter 调用方式
**问题**：`clickhouse-keeper-converter --help` 显示的参数文档与实际不符。
**原因**：`clickhouse-keeper-converter` 是 `clickhouse-keeper` 的符号链接，不是独立程序。
**正确方式**：`clickhouse keeper-converter`（clickhouse 主程序的子命令）

### 2. CK ZooKeeper 配置在 metrika.xml，不在 config.xml
**问题**：修改 `config.xml` 中的 `<zookeeper>` 段后 CK 仍连接旧 ZK。
**原因**：`config.xml` 中的 `<zookeeper>` 段是注释，`metrika.xml` 是实际生效配置。
**正确方式**：修改 `/etc/clickhouse-server/metrika.xml` 中的端口。
**验证**：`grep -n "<port>" /etc/clickhouse-server/metrika.xml` 确认无 2181。

### 3. Keeper 配置中 `<zookeeper>` 段的作用
**误解**：以为 Keeper 配置里写 `<zookeeper>` 段落会自动从 ZK 导入数据。
**实际**：`<zookeeper>` 段是让 Keeper 作为 ZK 代理（fallback），不用于导入。
**正确迁移方式**：使用 `clickhouse keeper-converter` 离线转换 snapshot，再启动 Keeper。

### 4. clickhouse-backup 备份不占额外磁盘空间
**原因**：`freeze_by_part=false` 时，`ALTER TABLE FREEZE` 通过硬链接冻结数据，不复制文件。
**实际占用**：备份包大小（displayed by `clickhouse-backup list`）= shadow/ 逻辑大小，实际磁盘占用以 `du -sh` 为准。

### 5. ZooKeeper 管理命令需要 JAVA_HOME
**症状**：`/home/yxpt/servers/zookeeper-3.7.2/bin/zkServer.sh` 报错 `JAVA_HOME is not set`。
**解决**：在命令前加 `export JAVA_HOME=/home/yxpt/servers/jdk1.8.0_141`。

### 6. clickhouse-keeper RPM 安装依赖冲突
**症状**：`clickhouse-server conflicts with clickhouse-keeper`。
**解决**：`rpm -Uvh --force --nodeps --nosignature <keeper-rpm>`。

### 7. 升级前副本必须 `is_readonly=0`
**原因**：`is_readonly=1` 的副本在 CK 重启后连接 Keeper 时会尝试同步失败，导致长时间异常。
**建议**：升级前执行 `SYSTEM RESTART REPLICA` 修复孤立 `is_readonly=1` 状态。

### 8. 维护窗口期间 ZK 不能重启
**原因**：ZK 重启期间 CK 副本的 `is_readonly=1` 会累积，启动期间会导致 Keeper 选主延迟。
**正确顺序**：CK 停机 → Keeper 启动 → CK 重启，切勿在 CK 停机期间重启 ZK/Keeper。

## 0. 备份数据目录结构（实际执行补充）

> clickhouse-backup v2.x 无 `backups_path` 配置键，本地备份目录由 ClickHouse disk 机制自动确定：
> `backup_path = <default_disk_path> + "/backup"` = `/data/clickhouse/backup/`

### 0.1 目录结构

```
/data/clickhouse/backup-data/    ← 实际备份数据存储（clickhouse:clickhouse）
    └── pre_upgrade_22_2_to_23_8_15.28.140.41_20260526_104007/
        ├── access/             ← 元数据，很轻
        ├── metadata/           ← 元数据，很轻
        ├── metadata.json       ← 元数据，很轻
        └── shadow/             ← 冻结的 data parts，通过硬链接指向原始数据，不额外占用空间

/data/clickhouse/backup -> /data/clickhouse/backup-data    ← 软链接（clickhouse-backup 读取的路径）
```

### 0.2 实际执行命令

在 6 台节点执行：

```bash
# 创建实际存储目录
mkdir -p /data/clickhouse/backup-data

# 创建软链接（覆盖默认 backup 目录，指向独立存储）
rm -f /data/clickhouse/backup
ln -sfn /data/clickhouse/backup-data /data/clickhouse/backup

# 确认结构
ls -la /data/clickhouse/ | grep backup
```

### 0.3 clickhouse-backup 数据机制说明

- `freeze_by_part: false` 时，备份对每张表执行 `ALTER TABLE FREEZE`
- 冻结后的 data parts 写入 `/data/clickhouse/shadow/`（硬链接，不额外占用磁盘空间）
- clickhouse-backup 遍历 shadow/ 打包成备份
- **恢复（restore）时才会真正占用空间**，freeze 阶段只做硬链接
- 备份列表查看：`clickhouse-backup -c /home/yxpt/ck/backup/clickhouse-backup/config.yml list`
- 备份实际大小（查看 shadow/）：`du -sh /data/clickhouse/backup-data/<backup_name>/shadow/`
