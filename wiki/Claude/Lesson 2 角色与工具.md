# Lesson 2：每个成员都有明确的角色和合适的工具

## 核心理念

人机协作团队**共用一份花名册、一组工件、一个工作空间**。

| 成员 | 独立资产 |
|------|---------|
| 人类 | 个人能力、判断、经验 |
| 智能体 | **独立凭证**、**技能**、**工具访问** |

## 角色多样性

不同智能体承担不同角色，常见类型：

- **数据分析智能体**：拥有数据查询/分析任务
- **设计标准智能体**：持有并执行设计规范
- **研究综合智能体**：执行研究综合
- **QA 智能体**：拥有代码审查/测试任务
- **Release Manager 智能体**：管理发布流程

> 关键：每个角色**职责清晰**、**工具匹配**、**边界明确**。

## 智能体的衍生能力

当任务启动时，智能体可以**衍生其他智能体**：

> "一个智能体可能会衍生出其他智能体，确保具体任务由具备合适记忆和适当访问权限的智能体处理。"

例如：项目负责人智能体 → 衍生出数据分析智能体 + QA 智能体。

## 角色与工具的匹配

智能体**必须拥有完成任务所需的全部工具**：

| 角色 | 需要的工具 |
|------|----------|
| 数据分析 | BigQuery |
| QA | Playwright MCP |
| 代码审查 | 代码仓库 + 测试框架 |
| 研究综合 | 文档库 + 网络搜索 |

## 为什么清晰角色至关重要

> **没有清晰角色，人们会在私下运行自己的 AI 舰队，导致工作重复、团队上下文碎片化。**

### 反面案例

- 每个人都用自己的 AI 做同一件事
- 不同 AI 的结果不一致，团队无统一数据
- 责任无人认领

### 正面案例

- **指标追踪**：一个智能体做一次，所有人看同一组数字
- **代码 review**：QA 智能体统一标准
- **研究综合**：研究智能体统一方法论

## Skill Files 的作用 [[Skill Files 角色定义|详见]]

Anthropic 工程团队发现：**编写 skill files 定义智能体角色**，能带来三个明显好处：

1. **责任追踪**：人类能快速定位"这件事归谁"
2. **专业化简单**：写一次，全公司可复制
3. **能力扩展容易**：项目复杂时**直接加新智能体 + 新 skill file**
   - 案例：增加 release manager 智能体处理版本发布

## Anthropic 的具体清单

- [ ] **明确的任务集**：团队的人类和智能体协议分工
- [ ] **共享线程**：人类和智能体在同一线程工作，任何人能接续
- [ ] **合适工具**：每个人/智能体都有完成工作所需的工具
- [ ] **角色描述**：智能体的角色和范围有明确文档

## 自检问题 2 和 3

> **问题 2**：能否写出团队花名册（含智能体），明确每个成员负责什么？
> **问题 3**：每个人类和智能体是否有合适的工具完成工作？
