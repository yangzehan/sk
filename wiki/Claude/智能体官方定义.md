# 智能体的官方定义（Anthropic）

## 核心定义

> **Anthropic 官方定义**：
> "Agents are systems where LLMs **dynamically direct their own processes and tool usage**, maintaining control over how they accomplish tasks."

**中文翻译**：
> **智能体是 LLM 动态指导自身流程和工具使用的系统，在如何完成任务方面保持控制权。**

## 关键短语

> **"...deciding for itself how to achieve what users want, rather than following a fixed script."**

> "**自主决定**如何达成用户目标，而不是**遵循固定脚本**。"

## 架构区分：Workflows vs Agents

Anthropic 把所有变体统称为 **agentic systems**，但做了**关键架构区分**：

| 类型 | 控制流 | 自主性 |
|------|--------|--------|
| **Workflows（工作流）** | 通过**预定义代码路径**编排 | 人类/代码决定流程 |
| **Agents（智能体）** | LLM **动态指导**自身流程和工具使用 | **LLM 自主决定** |

### 形象理解

- **Workflow** = 流水线工厂（每个工位做什么是固定的）
- **Agent** = 自主机器人（自己决定下一步该做什么）

## 智能体的核心特征

### 工作方式

1. 从人类用户的**命令或交互式讨论**开始
2. 任务明确后，**自主规划和操作**
3. 执行过程中，从环境获取"ground truth"（工具调用结果、代码执行输出）
4. 可在**检查点暂停**获取人类反馈，或遇到阻塞时暂停
5. 完成时终止，或到达停止条件（最大迭代次数）

### 本质

> **"Agents can handle sophisticated tasks, but their implementation is often straightforward. They are typically just LLMs using tools based on environmental feedback in a loop."**

> 智能体通常只是**在循环中根据环境反馈使用工具的 LLM**。

## 何时使用智能体

### ✅ 适合

- **开放性问题**：难以预测所需步骤数
- **无法硬编码固定路径**
- LLM 可能运行**多轮**
- 需要对其决策有**一定信任**
- 适合在**可信任环境中规模化**

### ❌ 不适合

- 任务能简单 LLM 调用解决时
- 任务定义明确且工作流可预定义（用 Workflow 更合适）
- 成本/延迟比性能更重要时

## 五大 Workflow 模式（智能体的组件）

> 这些不是智能体本身，但常作为智能体的**构建模式**。

### 1. Prompt Chaining（提示链）
- 任务分解为步骤序列
- 中间可加**门控检查（gate）**
- **用例**：营销文案 → 翻译；大纲 → 检查 → 正文

### 2. Routing（路由）
- 对输入**分类**并导向专门的下游任务
- **用例**：客服问题分类走不同流程

### 3. Parallelization（并行化）
- **Sectioning**：拆分子任务并行
- **Voting**：多次执行同一任务
- **用例**：guardrails、内容审核

### 4. Orchestrator-Workers（编排者-工作者）
- 中央 LLM **动态分解**任务、委派给 workers、综合结果
- **与并行化的差异**：子任务**不是预定义**的
- **用例**：复杂多文件代码修改

### 5. Evaluator-Optimizer（评估者-优化者）
- 一个 LLM 生成，另一个评估反馈，形成循环
- **用例**：文学翻译、多轮搜索

## 智能体的现实形态

Anthropic 自己使用的智能体：

- **SWE-bench coding agent**：基于任务描述编辑多文件
- **Computer use**：Claude 使用计算机完成任务

客户使用的智能体：

- **客服智能体**：对话 + 工具集成，按成功解决次数收费
- **编码智能体**：自动化测试验证 + 智能体迭代

## 三大核心原则

实现智能体时 Anthropic 遵循：

1. **Maintain simplicity** — 保持智能体设计的简洁性
2. **Prioritize transparency** — 优先透明性，明确展示规划步骤
3. **Carefully craft your ACI** — 通过工具**文档和测试**精心设计智能体-计算机接口

## 智能体 vs Multiplayer Agents

| 维度 | Agent（通用） | Multiplayer Agent |
|------|------------|------------------|
| 用户数 | 单人/单任务 | **多人类同时** |
| 工作位置 | IDE/聊天窗口 | **团队协作工具** |
| 记忆 | 会话/任务级 | **持久跨会话** |
| 凭证 | 借用人类 | **独立凭证** |

> Multiplayer Agents 是 Agent 概念的**团队协作扩展**——保留了"动态自主"的核心，增加了"团队成员"的社会属性。
