# 后台机制 - 三大处理器

> pi-hermes-memory 在 session 内部有 3 个**常驻处理器**，分别处理"何时存点 memory"。
> 全部基于 [[pi-coding-agent]] 的扩展事件订阅 + 子进程异步执行。

| 处理器 | 触发点 | 同步/异步 | 频率 |
|---|---|---|---|
| **Background Review** | `turn_end` | fire-and-forget | 10 turn **或** 15 tool call |
| **Session Flush** | `session_before_compact` / `session_shutdown` | await（compact）/ fire-and-forget（shutdown） | 每次 compact / shutdown 各 1 次 |
| **Correction Detection** | `message_end` (user) → `turn_end` | await（与 background 不同） | 至少间隔 3 turn |

---

## 1. Background Review（`handlers/background-review.ts`）

### 状态

```ts
let turnsSinceReview = 0;       // 自上次 review 至今过了几 turn
let toolCallsSinceReview = 0;   // 自上次 review 至今的 tool call 数
let userTurnCount = 0;          // 累计 user 消息数（防误触发）
let reviewInProgress = false;   // 互斥锁
```

### 事件订阅

```ts
pi.on("message_end", e => { if (e.message.role === "user") userTurnCount++; });
pi.on("turn_end", async (event, ctx) => { /* 主逻辑 */ });
```

### 触发判定（`turn_end` 内）

```ts
turnsSinceReview++;
if (!config.reviewEnabled) return;     // 总开关
if (reviewInProgress) return;          // 已经在跑就不重入

// 数本 turn 的 tool call（注释强调：只数本 turn 的，不是整个分支，
// 否则永远不归零导致每 turn 都触发）
if (msg.role === "assistant") for block of content: if block.type === "toolCall" toolCallsSinceReview++;

const turnMet  = turnsSinceReview   >= config.nudgeInterval;     // 10 turn
const toolMet  = toolCallsSinceReview >= config.nudgeToolCalls;   // 15 call
if (!turnMet && !toolMet) return;                                // 二选一
if (userTurnCount < 3) return;                                   // 至少 3 轮用户消息
```

→ 总结：`(turns >= 10 || toolCalls >= 15) && userTurns >= 3 && !inProgress && enabled`

### 触发后流程

1. **重置计数器**：`turnsSinceReview = 0; toolCallsSinceReview = 0;`
2. **置锁**：`reviewInProgress = true`
3. **收集对话**：`ctx.sessionManager.getBranch()` → `collectMessageParts(entries)` → 字符串数组
4. **太短就放弃**：`allParts.length < 4` 直接 return
5. **截取窗口**：`applyRecentMessageLimit(parts, config.reviewRecentMessages)`，`0` = 全部
6. **拼 prompt**：
   ```
   COMBINED_REVIEW_PROMPT
   --- Current Memory --- <MEMORY>
   --- Current User Profile --- <USER>
   --- Current Project Memory --- <PROJECT>     ← 仅 projectStore 存在时
   --- Conversation to Review --- <对话快照>
   ```
7. **不 await**：fire-and-forget spawn 子 `pi -p`，timeout 120s
8. **then 回调**：退码 0 + stdout 非空 + 不含 "nothing to save" → `ctx.ui.notify("💾 Memory auto-reviewed and updated")`
9. **catch 回调**：所有错误静默吞掉，下轮再试

### 关键设计点

- **完全异步**：不 await 子进程，主聊天永远不会被 review 拖慢
- **进程隔离**：review 在独立 `pi -p` 子进程里跑，**不会污染**主 session memory
- **自我递归保护**：`reviewInProgress` 锁

## 2. Session Flush（`handlers/session-flush.ts`）

> **它自己不直接写盘**，而是 **spawn 一个子 `pi -p` 跑 `FLUSH_PROMPT`**，让那个 LLM 用 `memory` 工具增删改，最终由 `MemoryStore.saveToDisk()` 原子写。

### 状态

```ts
let userTurnCount = 0;
```

### 事件

```ts
pi.on("message_end", e => { if (e.message.role === "user") userTurnCount++; });
```

### 触发点 1：`session_before_compact`（compaction 之前）

```ts
pi.on("session_before_compact", async (event, ctx) => {
  if (!config.flushOnCompact) return;
  await flush(ctx, event.signal, 30000);  // ← 等 30s
});
```

### 触发点 2：`session_shutdown`（session 关闭）

```ts
pi.on("session_shutdown", async (event, ctx) => {
  if (!config.flushOnShutdown) return;
  flush(ctx, undefined, 10000).catch(() => {});  // ← 不 await，10s 后放弃
});
```

### `flush()` 内部

```ts
if (userTurnCount < config.flushMinTurns) return;  // 默认 6 轮
const entries = ctx.sessionManager.getBranch();
const parts = collectMessageParts(entries, config.flushRecentMessages);
const flushMessage = FLUSH_PROMPT + "\n--- Conversation ---\n" + parts.join("\n\n");
await execChildPrompt(pi, flushMessage, config, { signal, timeoutMs });
```

### `FLUSH_PROMPT` 全文

```
[System: The session is being compressed. Save anything worth remembering —
prioritize user preferences, corrections, and recurring patterns over
task-specific details.]
```

### 关键设计点

- **compaction 时 await**：让 flush 跑完再 compact（30s）
- **shutdown 时 fire-and-forget**：不让 pi 等 memory（10s 短超时）
- **没有 turn_end 触发**：flush 跟 LLM turn 完全无关，**不会**与 background review 重复
- **真正写盘的是谁**：`MemoryStore.saveToDisk()` 用 `temp file + fs.rename` 原子写

## 3. Correction Detection（`handlers/correction-detector.ts`）

> **2-pass 过滤 + 速率限制 + 同步存 failure 记忆**。

### 状态

```ts
let pendingCorrection = false;       // 标记本 turn 有没有检测到纠正
let turnsSinceLastCorrection = 3;    // 限速器：初始为 3（让首次纠正能立刻触发）
let correctionInProgress = false;    // 互斥锁
```

### A. 文本模式识别（`isCorrection()`）

四类模式（`src/constants.ts:165-220`）：

| 类型 | 数量 | 行为 |
|---|---|---|
| **CORRECTION_NEGATIVE_PATTERNS** | 6 条 | 先匹配，命中即 `return false`（防误报） |
| **CORRECTION_STRONG_PATTERNS** | 7 条 | 命中即 `return true`（高置信） |
| **CORRECTION_WEAK_PATTERNS** | 4 条 | 必须 anchor 在开头 + 后面跟指令词 |
| **CORRECTION_DIRECTIVE_WORDS** | 23 个 | 弱信号后必须跟其中一个 |

**强信号**（`constants.ts:165-174`）：
```ts
/don'?t do that/i,        /not like that/i,
/^I said\b/i,             /^I told you\b/i,
/we already discussed/i,  /^please don'?t/i,
/^that'?s not what I/i,
```

**弱信号**（必须 `^` 在开头）：
```ts
/^no[,\.\s!]/i,    /^wrong[,\.\s!]/i,
/^actually[,\.\s]/i, /^stop[,\.\s!]/i,
```

**否定信号**（抑制）：
```ts
/^no worries/i, /^no problem/i, /^no thanks/i, /^no need/i,
/^actually.{0,10}(looks? great|perfect|good|correct|right)/i,
/^stop.{0,5}(there|here|for now)/i,
```

**指令词**：
```ts
use, don't, dont, do, try, make, run, install, add, remove, delete, change,
fix, put, set, write, go, stop, start, the, that, this, it
```

### B. 匹配流程

```ts
// 阶段 0：否定（先匹配）—— 匹配上直接 false
for (const pattern of negativePatterns) {
  if (pattern.test(text)) return false;
}

// 阶段 1：强信号 —— 匹配上直接 true
for (const pattern of strongPatterns) {
  if (pattern.test(text)) return true;
}

// 阶段 2：弱信号 —— 还要看后面有没有"指令词"
for (const pattern of weakPatterns) {
  if (pattern.test(text)) {
    const match = pattern.exec(text);
    if (match.index === 0) {                              // ← 弱 pattern 必须在文本开头
      const remainder = text.slice(match[0].length).trim();
      if (hasDirectiveWord(remainder, directiveWords)) return true;
    }
  }
}
return false;
```

### C. 触发流程

**事件 1：`message_end`（user）**

```ts
if (e.message.role !== "user") return;
const text = getMessageText(e.message);  // 容错：非 string / 无 content 返回 null
if (!text) return;
if (isCorrection(text, config)) pendingCorrection = true;
```

**事件 2：`turn_end`**

```ts
if (!pendingCorrection) { turnsSinceLastCorrection++; return; }
pendingCorrection = false;

// 限速：至少间隔 3 turn
if (turnsSinceLastCorrection < 3) return;
if (correctionInProgress) return;

turnsSinceLastCorrection = 0;
correctionInProgress = true;
try {
  // 1. 拿最近 6 段对话
  const recentParts = [...].slice(-6);

  // 2. 拼 CORRECTION_SAVE_PROMPT：含当前 MEMORY/USER/PROJECT + 最近对话
  const prompt = [...].join("\n");

  // 3. await spawn 子 pi -p，30s timeout（与 background review 不同：这里 await）
  const result = await execChildPrompt(pi, prompt, config, { signal: ctx.signal, timeoutMs: 30000 });

  // 4. 同步存一条 failure 类记忆（与 background review 不同：直接 addFailure）
  await store.addFailure(directive, {
    category: "correction",
    failureReason: "User corrected the agent",
    project: projectStore ? projectName : undefined,
  });

  // 5. 同步到 SQLite
  if (dbManager) syncMemoryEntry(dbManager, {...});
} catch {} finally { correctionInProgress = false; }
```

### D. 与 Background Review 的关键区别

| 维度 | background review | correctionDetection |
|---|---|---|
| 触发频率 | 10 turn / 15 toolCall | 至少间隔 3 turn |
| 是否 await | ❌ fire-and-forget | ✅ await（确保存了） |
| 信号 | 单纯 turn / toolCall 计数 | 文本 regex 匹配 |
| 副作用 | 仅让子 LLM 决定存啥 | **同步** 存一条 failure（`category: "correction"`） |
| 写盘 | 间接（子进程写） | 直接（`store.addFailure`） |

## 三个事件生命周期对比

按 [[pi-coding-agent]] 扩展事件时序：

| 事件 | 触发时机 | 一个 session 里几次 |
|---|---|---|
| `message_start` / `message_end` | 单个消息（user / assistant / toolResult）完成 | 每消息 1 次 |
| `turn_start` / `turn_end` | 一次 LLM 响应（可能带 N 个 tool call）完成 | 每 turn 1 次（一个 prompt 内可能 N 个 turn） |
| `agent_end` | 用户**一次 prompt** 完全结束 | 每 user prompt 1 次 |
| `session_before_compact` | `/compact` 或自动 compaction 启动前 | 每次 compact 1 次 |
| `session_shutdown` | session 销毁 | session 整个生命周期**只 1 次**（或 `/new`/`/resume`/`/fork`/`/clone` 切换时各 1 次） |

### 一次 user 消息的完整时序（带 tool call）

```
user 发消息
  ↓
message_start (user) / message_end (user)
  ↓
turn_start (turn 1)
  ├─ LLM 决定调 tool
  ├─ tool_execution_start
  ├─ tool_call
  ├─ tool_result
  ├─ tool_execution_end
  └─ turn_end (turn 1)              ← background review 计数 +1
  ↓
turn_start (turn 2)                 ← LLM 看完 tool 结果再调另一个 tool
  ├─ tool_execution_start
  ├─ tool_call
  ├─ tool_result
  ├─ tool_execution_end
  └─ turn_end (turn 2)              ← background review 计数 +1
  ↓
... (N 个 turn)
  ↓
turn_start (final)
  └─ turn_end (final)
  ↓
agent_end
```

### session 销毁触发

```
session 结束触发条件之一：
├─ /new           → session_shutdown → session_start (reason: "new")
├─ /resume        → session_shutdown → session_start (reason: "resume")
├─ /fork 或 /clone → session_shutdown → session_start (reason: "fork")
├─ Ctrl+C / Ctrl+D / SIGHUP / SIGTERM → session_shutdown
└─ /compact       → session_before_compact → session_compact（session 不结束）
```

### Session flush vs turn_end 会重复吗？

**不会**。Session flush 订阅的是 `session_before_compact` / `session_shutdown`，与 `turn_end` 完全不在同一时点。

唯一"看起来重复"的情况：关闭 session 前的最后一个 `turn_end` 触发 background review，紧接 `session_shutdown` 触发 flush。但因 `add` 内部去重，**不会产生重复条目**。
